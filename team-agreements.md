# Teamafspraken

## Workflow

### Branching

- We werken met main, dev, en feature branches
- Feature branches mogen naar dev gemerged worden na een positieve review met approval
- Dev mag naar main gemerged worden als dev klaar is voor een release

### Pull Requests

- Voordat een branch wordt gemerged moet er een pull request komen
- We gebruiken het FDND Agency template voor onze Pull Requests

### Issues En Projectbord

- Er wordt altijd vanuit een issue gewerkt
- Wanneer wordt besloten dat een issue deze sprint wordt opgepakt wordt die in het begin van die sprint naar "todo" verplaatst
- Zodra een issue daadwerkelijk is opgepakt wordt deze naar "In progress" verplaatst
- Als de developer klaar is/denkt te zijn met het issue gaat deze naar "In review"
- Pas als een issue gereviewed én geapproved is mag deze naar "Done"
- Elke standup wordt naar het projectbord gekeken

## Communicatie

- Online communicatie gaat over het algemeen via teams, en discord als dat niet werkt / kan / als backup
- We streven ernaar binnen 24 uur op studie-dagen op berichten te reageren
- Afwezigheid van te voren melden
- Bij langdurige stilte (3 dagen) wordt de docent ingeschakeld
- Bij blokkades vragen we eerst hulp aan elkaar (via teams als online), daarna eventueel aan de docent. We kunnen elkaar altijd om hulp vragen.
